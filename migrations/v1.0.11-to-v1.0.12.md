# Migration Guide: `ios-v1.0.11` → `ios-v1.0.12`

---

## Deprecations (non-breaking)

### `AstroConnect.preload(configuration:onSuccess:onError:)` is deprecated

A new `preload` overload delivers a single terminal result through `onPreloadEnded(reason)` so integrators can distinguish a fully loaded page from a deferred handoff (e.g. when a biometric prompt is shown only after `AstroConnectView` is presented).

The deprecated overload still works. For backward compatibility, `onSuccess` is now also invoked for the deferred case so existing integrators are not left waiting indefinitely.

```swift
// BEFORE (v1.0.11) — still works, but deprecated
AstroConnect.preload(
    configuration: configuration,
    onSuccess: { /* SDK ready */ },
    onError: { error in /* failed */ }
)

// NOW (v1.0.12)
AstroConnect.preload(
    configuration: configuration,
    onPreloadEnded: { reason in
        switch reason {
        case .loaded:
            // page fully loaded — opens instantly
        case .deferred:
            // preload ended without full load; biometric or live view will handle the rest
        case .failed(let error):
            // preload failed
        @unknown default:
            // future-proof against new reasons added in later SDK versions
        }
    }
)
```

---

## New Features (optional)

### Pre-load load timeout *(since v1.0.12)*

`AstroConnect.preload` now applies the SDK load timeout to the preload phase. If the page neither loads nor errors within the timeout, the callback receives `.failed` (or the legacy `onError`) instead of hanging indefinitely.

### Deferred biometric prompt during preload *(since v1.0.12)*

When the SDK requires biometric authentication to finish loading, the prompt is automatically deferred until `AstroConnectView` is presented. The user is never prompted before the SDK is on screen.

### Preload configuration mismatch *(since v1.0.12)*

If you call `preload(configuration:)` and later present `AstroConnectView` with a different configuration, the previously preloaded session is discarded. Your `onPreloadEnded` callback (or the legacy `onError`) is now invoked with `.failed(.invalidConfiguration)` so it cannot be left hanging.
