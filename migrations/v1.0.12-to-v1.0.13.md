# Migrate from v1.0.12 to v1.0.13 — `AstroResult.closed` carries `(code, message)`

`AstroResult.closed` now carries two associated values, `code: String` and `message: String`, describing **why** the SDK closed. Any `switch` over `AstroResult` must be updated.

`code` is a short machine-readable identifier in `UPPER_SNAKE_CASE`. `message` is a human-readable description. Both are plain strings — there is no enum, no whitelist, and no mapping. The SDK fixes the values it emits itself (see below) and may add new `code` values for in-SDK close paths in future releases without breaking the API.

## Before

```swift
AstroConnectView(configuration: configuration) { result in
    switch result {
    case .success:
        // ...
    case .closed:                                  // no payload
        analytics.log("sdk_closed")
    case .failure(let error):
        // ...
    case .event(let event):
        // ...
    }
}
```

## After

```swift
AstroConnectView(configuration: configuration) { result in
    switch result {
    case .success:
        // ...
    case .closed(let code, let message):           // now carries (code, message)
        analytics.log("sdk_closed", properties: ["code": code, "message": message])
    case .failure(let error):
        // ...
    case .event(let event):
        // ...
    }
}
```

## Codes emitted by the SDK itself

The following close codes originate in native code and emit fixed values:

| code | source | message |
|---|---|---|
| `CLOSED_BY_USER_HEADER_BUTTON` | User tapped the built-in header close button | `User tapped the close button` |
| `CLOSED_BY_HOST_APP` | You called `AstroConnectController.close()` | `Closed by host integrator` |
| `CLOSED_BY_SYSTEM_DISMISS` | View disappeared without an explicit close call (back-swipe, sheet drag, host removal) | `View was dismissed` |
| `UNKNOWN` | Fallback when the close payload is missing or malformed | `` (empty string) |

Additional codes (for example `CLOSED_BY_USER_NAVIGATED_BACK`, `CLOSED_BY_USER_SIGNED_OUT`, `CLOSED_BY_USER_CANCELLED_PIN`, `CLOSED_BY_USER_DISMISSED_ERROR`) are emitted by SDK flows. They all follow the `CLOSED_BY_*` `UPPER_SNAKE_CASE` convention. The list is not exhaustive and may grow in future releases; treat any unrecognized `code` as a generic close.

## Other affected APIs

- `AstroConnect.onClose` now has the signature `((String, String) -> Void)?`. If you set this closure directly, update it to accept `(code, message)`.
- `AstroConnectController.close()` takes no arguments. The SDK emits `.closed(code: "CLOSED_BY_HOST_APP", message: "Closed by host integrator")` for every call to it.

## Also in this release — `showCloseButton` and `autoSize` removed

The previously deprecated `AstroConfiguration` parameters `showCloseButton` and `autoSize` have been removed entirely. Both were deprecated in v1.0.10 with `@available(*, deprecated, renamed: "showHeader")` and replaced by `showHeader`. Any code that still passes either label will fail to compile.

There is no behavioral change beyond the removal: `showHeader` continues to control header visibility exactly as it did in v1.0.12.

### Before

```swift
let configuration = AstroConfiguration(
    environment: "sandbox",
    appIssuer: "your-app-issuer",
    clientId: "your-client-id",
    partnerUserId: "user-123",
    accessToken: "...",
    showCloseButton: false,   // removed
    autoSize: true            // removed
)
```

### After

```swift
let configuration = AstroConfiguration(
    environment: "sandbox",
    appIssuer: "your-app-issuer",
    clientId: "your-client-id",
    partnerUserId: "user-123",
    accessToken: "...",
    showHeader: false         // replaces both
)
```

### Mapping

| Removed | Replace with |
|---|---|
| `showCloseButton: Bool?` | `showHeader: Bool?` |
| `autoSize: Bool?` | `showHeader: Bool?` |

`showHeader` defaults to `true` (the header bar with close button and co-branded logo is shown). Pass `showHeader: false` to hide the entire header bar — for example, when you render your own header and dismiss the SDK via `AstroConnectController.close()`.

### Caller-facing impact

- Any `AstroConfiguration(...)` call site that still uses `showCloseButton:` or `autoSize:` will produce a compile error. Remove the argument and, if header visibility was being toggled, pass `showHeader:` with the equivalent value.
- The properties `AstroConfiguration.showCloseButton` and `AstroConfiguration.autoSize` are no longer readable. Read `AstroConfiguration.showHeader` instead.
