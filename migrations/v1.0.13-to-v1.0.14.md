# Migrate from v1.0.13 to v1.0.14 — typed `AstroStyle` colors are now `UIColor?`

The color fields on the typed `AstroStyle` API changed from hex `String?` to `UIColor?` — the same color representation used across UIKit. This affects:

- `AstroStyle.backgroundColor`
- `AstroHeaderStyle.backgroundColor`
- `AstroHeaderStyle.borderColor`

Any code that passes a hex string to one of these fields will no longer compile. You have two options: pass a `UIColor` (recommended), or keep the hex string by moving the value into the `styleOverrides` dictionary.

## Before

```swift
let style = AstroStyle(
    backgroundColor: "#FFFFFF",
    header: AstroHeaderStyle(
        backgroundColor: "#EFEFEF",
        borderColor: "#CCCCCC"
    )
)
```

## After — option 1: pass a `UIColor` (recommended)

Each field now accepts a `UIColor`. Any standard UIKit construction form works:

```swift
let style = AstroStyle(
    backgroundColor: UIColor(white: 1, alpha: 1),
    header: AstroHeaderStyle(
        backgroundColor: UIColor(red: 0.937, green: 0.937, blue: 0.937, alpha: 1),
        borderColor: UIColor(red: 0.8, green: 0.8, blue: 0.8, alpha: 1)
    )
)
```

All three honor the `UIColor` alpha component for partial transparency.

## After — option 2: keep the hex string via `styleOverrides`

If you must keep colors as hex strings — for example, theme values fetched from a remote configuration service — move them into `AstroConfiguration.styleOverrides` instead of the typed `AstroStyle`. The dictionary accepts both hex strings (6- or 8-digit `#RRGGBB` / `#RRGGBBAA`) and `UIColor` values for color leaves.

The header colors have a dedicated nested key. Move `AstroHeaderStyle(backgroundColor: "#EFEFEF", borderColor: "#CCCCCC")` into `styleOverrides["header"]["backgroundColor"]` / `["borderColor"]` — these style the native header and follow the same precedence (`styleOverrides` wins over the typed `AstroStyle.header.*`):

```swift
let configuration = AstroConfiguration(
    environment: "sandbox",
    appIssuer: "your-app-issuer",
    clientId: "your-client-id",
    partnerUserId: "user-123",
    accessToken: "...",
    styleOverrides: [
        "backgroundColor": "#FFFFFF",
        "header": [
            "backgroundColor": "#EFEFEF",
            "borderColor": "#CCCCCC"
        ]
    ]
)
```

See [Free-form overrides via `styleOverrides`](../STYLE-TOKENS.md#free-form-overrides-via-styleoverrides) for the full key catalog and contract. Note that the typed `AstroStyle` and `styleOverrides` are independent: `styleOverrides` mirrors the typed key shape but is a separate free-form passthrough.

## Mapping

| Field | Before | After |
|---|---|---|
| `AstroStyle.backgroundColor` | `String?` (hex) | `UIColor?` |
| `AstroHeaderStyle.backgroundColor` | `String?` (hex) | `UIColor?` |
| `AstroHeaderStyle.borderColor` | `String?` (hex) | `UIColor?` |

## Caller-facing impact

- Any call site that passes a hex `String` to one of the three fields above will produce a compile error. Convert the value to a `UIColor`, or move it into `styleOverrides`.
- The non-color fields on `AstroStyle` and `AstroHeaderStyle` (e.g. `borderWidth`, `paddingHorizontal`, `paddingVertical`) are unchanged.
- This is the only breaking change in v1.0.14. The rest of the style-customization surface is additive.
